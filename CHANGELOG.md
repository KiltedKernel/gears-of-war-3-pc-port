# Changelog

## Unreleased

**Mods** (docs/MODDING.md)
- Mods in multiplayer: each mod says who needs it (`side = everyone | host | client` in its mod.ini). A player whose
  `everyone` mods differ from the session's is not let in, and the game says which mods the session uses; `host` mods
  (a game mode's rules) act in matches you host, `client` mods (your own view) are never compared.
- Servers can require mods: `gow3_server --mods <folder>`, and a `server.ini` for every server setting
  (examples/server/server.ini). The server prints the mods players need and their fingerprint.
- Mods can need other mods (`requires = ...`) and name their game (`game = gears3`): a mod whose requirement is
  missing or off is left off, with the reason in the log, the launcher and `modtool.py mods`.
- Mods shared for the Xbox 360 install as they are: a .zip without a mod.ini gets a mod folder and a mod.ini (launcher
  and `modtool.py install`); bare packages, Coalesced files and movies, or files inside the game's folders, go where
  the game expects them. `modtool.py check` points out code patches, which cannot apply to the recompiled game.
- Sample mods for each side: Wider view (client: camera field of view), Horde: big bank and Horde: interest (host;
  the second requires the first), Lancer ammo (everyone), next to the chapter, menu text and unlock examples.
- The launcher's Mods tab shows who needs each mod and why a mod is not loaded.

**The trilogy** (docs/TRILOGY.md)
- The Gears of War 1 conversion tools join the repository (levelinject, objcopy, meshes, materials, BSP, lighting,
  cover, navmesh, Kismet), with `tools/trilogy.py build <recipe>`: a whole conversion from the player's own Gears 1
  and Gears 3 discs into a mod in one command, its navmesh generated by running Gears 3's own builder in the game.
- First recipe, `gears1_prison`: Gears 1's opening in Gears 3's campaign (the cell, the cutscene, Dom, the corridor),
  about three minutes to build. tests/g1_follow_dom.txt.

**Tests**
- tools/playtest.ps1 gave the game the input script's path relative to the repository while the game runs in
  build\: a relative path played no input at all. It now passes the full path.
- Fix: an intermittent crash of a game that joined a match. Gears 3 closes its session handles with NtClose, and the
  kernel took the session handle's number for an object's address. NtClose now closes sessions, and answers "invalid
  handle" (as the console does) for anything that is not an open object, instead of destroying freed memory.

## 0.2.1 (2026-10-15)

Fixes: the setup accepts Gears of War 3 discs again, works on PCs with WSL, and the frame-rate unlock keeps the
network healthy.

- Logs are safe to post: network lines keep only the first two numbers of public addresses and hide join codes
  (`GOW3_LOG_ADDRESSES=1` logs them in full).
- CONTRIBUTING.md and a bug report form for GitHub issues.
- Multiplayer: a Gears of War 2 PC port game or server is turned away with a reason ("this is for Gears of War 3, not
  Gears of War 2"), in the game and in the launcher's server list, instead of the two games mixing.
- Frame-rate unlock: the engine's tick is capped at the chosen frame rate instead of not at all. Uncapped, it ticked
  as fast as the CPU allowed while loading; in the Gears of War 2 port that flooded the network and broke campaign
  co-op. Versus over System Link re-verified.
- Fix: the setup's disc check expected the wrong default.xex (Gears of War 2's hash), so it turned every Gears of War 3
  disc away.
- Fix: on a PC with WSL the setup ran WSL's bash (System32\bash.exe) instead of Git for Windows', and step 2 failed.

## 0.2.0 (2026-10-14)

Multiplayer with friends, a player profile, and a settings audit.

**Multiplayer** (docs/MULTIPLAYER.md)
- The game's System Link runs over the internet: the port gives the game a virtual LAN carried over one UDP port to
  a session hub. Parties, the System Link browser, lobbies and matches work as the game made them.
- No host or join to choose. **With friends**: games on one network (or one PC) find each other by themselves; over
  the internet, a friend types your code (your public address and port, `XXXXX-XXXXX`, the port opened by UPnP).
  A code that points back into your own network is recognised and connected there. **On a server**: everyone on a
  `gow3_server.exe` shares one lobby (or a private room), so the System Link list shows every party on it.
- Everything is said in the game: a message panel over the picture when you connect, when someone joins or leaves,
  when a friend's code does not answer (and what to do), when the connection drops (it reconnects).
- Two copies of the game on one PC are two players: the second gets its own profile, player id and log.
- The launcher's **Multiplayer** tab: gamertag; Offline / With friends / On a server; your code (Copy) and a friend's
  code with **Check**; a server list with players, ping and who is online, Add, Remove and **Run my own**; private
  room and password; Windows Firewall status with **Allow** / **Fix**; port and UPnP.
- `gow3.ini [network]`: online, server, servers, join, room, password, port, upnp; offline by default, sending
  nothing to the network.
- Verified on one PC (tools/mp_test.ps1): two games join a System Link party and play Private Team Deathmatch
  together with no code, as two copies of one install, and on a server; a code that cannot be reached falls back to
  the game on the network. Horde, Beast and campaign co-op over System Link: both players in the same wave, or in
  the host's campaign. Not yet tested between two PCs.

**Profile**
- `profile.ini` in the save folder: a gamertag shown to other players and a random player id, kept between runs.
  Existing saves keep working.

**Settings**
- Every gow3.ini setting was traced to the code that reads it. Removed because they did nothing: `bloom` (Gears 3
  never reads its own bloom flag), `texture_streaming_fix`, `black_shading_fix` and `shadow_resolution` (Gears 2
  leftovers). Old gow3.ini files still load.
- Turning sound off no longer risks a crash: the audio system runs muted instead of not at all.
- Launcher: labels and check boxes are drawn on the page's own background.

**Fixes**
- XamVoiceCreate reports "no headset" instead of returning an unset voice.

## 0.1.1 (2026-10-13)

Housekeeping: names, license notices, and the XEX decryption key no longer stored in the repository.

- The decryption key for the game's executable is no longer in this repository: tools/xex_unpack.py reads it from
  XenonRecomp's sources, which the setup downloads (the setup now builds XenonRecomp before decrypting). Old commits
  were rewritten without it.
- THIRD_PARTY_NOTICES.md: the licenses of Xenia (BSD-3-Clause), XenonRecomp (MIT), o1heap and unordered_dense (MIT),
  and the components the setup downloads (FFmpeg's LGPL among them).
- Names inherited from the Gears of War 2 port this runtime started from are gone: kernel files are x360_*.cpp, the
  recompiled game code library is gow3_ppc, the GPU bridge is port_gpu.h / portgpu, Xenia's build options are XE_PORT*
  (patch tools/xenia-gow3.patch), its build folder build-gow3. Two dead Gears 2 modules (its menu mouse and settings
  code, never started in Gears 3) were removed, with three gow3.ini keys that only they read (distortion, fog_volumes,
  self_shadowing: they had no effect in Gears 3).
- Scripts read the install's folders from tools/local.cmd (tools/local.sh for bash, modtool.py).

## 0.1.0 (2026-10-13)

First release: Gears of War 3 as a native Windows program, made from the player's own disc image.

**Install**
- `Setup.cmd`: an installation wizard (disc image, install location, shortcuts on the desktop and in the Start menu,
  build tools, progress with a log, finish). Missing build tools (Visual Studio 2022 Build Tools with clang-cl, CMake
  and Ninja; Python 3; Git) are installed with winget when the player agrees. Rerunning continues after a failure.
- `tools\setup.ps1`: the same from a console. It checks the disc's `default.xex` is the version the port was made for,
  recompiles the game code (XenonRecomp, pinned and patched), builds Xenia's GPU and audio (pinned and patched) and the
  port, and draws the keyboard and mouse prompt icons.

**Game**
- Boots from the disc's files; logo movies (or `-nointro`); title screen, menus and options.
- The whole campaign loads and plays: every chapter of Acts I-V was booted and played for minutes in tests, with
  cutscenes, combat, turret and vehicle sections; checkpoints save and Continue loads them.
- Offline modes: Campaign (Standard, Arcade, Select Chapter), Horde, Versus with bots and Beast (Private).
- Frame rate unlock (30 to 240 fps; game speed unaffected), resolution scaling, 16x anisotropic filtering, effect
  toggles, vsync, fullscreen (F11 / Alt+Enter).
- Keyboard and mouse: native mouse look, rebound actions, menus with the mouse (hover, click, wheel, sliders), button
  prompts that follow the device used last (drawn keyboard and mouse icons; Gears of War: Reloaded's as an opt-in).
  Controllers through XInput.

**Launcher**
- Display, graphics, effects, controls, audio and game settings (`build\gow3.ini`).
- Mods tab: installed mods in load order, on/off, load order, conflicts, install from a .zip, remove (to the Recycle
  Bin).

**Mods**
- Folders in `build\mods` with a `mod.ini` replace or add game files; priorities; the table of contents is merged at
  startup.
- Configuration fragments (`config\*.ini`) merged into the game's Coalesced files at startup; several mods stack.
- New campaign chapters (numbers 32-49) in Select Chapter, loading their own maps.
- `tools\modtool.py` (create, check, pack, install), `tools\campaign.py` (chapter fragments), examples in
  `examples\mods` (a new act and chapter, a menu string, unlock every chapter).

**For developers**
- Reverse-engineering documentation (`docs/REVERSE_ENGINEERING.md`) and the development journal
  (`docs/ENGINEERING_LOG.md`); tools for UE3 packages, Coalesced files, UnrealScript bytecode, textures and the XEX.
- Scripted playtests (`tools\playtest.ps1`, `tests\`) isolated from the player's saves, mods and settings; campaign
  coverage (`tools\chapter_test.py`).

**Known limits**
- No Xbox LIVE: online modes and the party features are unavailable.
- The build needs a C++ toolchain on the player's PC (the recompiled game code is made from their disc).
- Chapters have been played for their first minutes in tests, not each to its end.
